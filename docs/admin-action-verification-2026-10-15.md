# Admin action verification — 15 October 2026

## Verdict

The tested Admin business workflows are functional and enforce server-side authorization, confirmation, persistence and policy checks. This is **not yet an unrestricted production-readiness approval**. All 66 capability entries are accounted for below: 64 are in scope, with Agents and Payments excluded. A reachable page is not proof that every operation on that page passed. Rows explicitly identify fixture tests, read checks and remaining acceptance gaps.

## Changes made

- Removed the real SDE department (number 62) at the user's request; verified no assignments, positions or issued IDs referenced it, verified absence afterward, and recorded catalog.deleted. Its number is not reused.
- Added unused-department deletion in Company catalogs with a named confirmation dialog, active-Admin authorization, same-origin checking, in-use protection, transaction locking and audit. Browser dialog was opened and cancelled; no second real department was deleted.
- Fixed Manager role assignment to collect a missing qualification and validate the selected department before confirmation/ID generation. Pending role replies retain their workflow. Admin IDs remain role-locked.
- Enforced organization changes-disabled policy at catalog, employment-confirmation, ticket-allocation and account-deletion transaction boundaries.
- Fixed general security answers omitting imported vulnerability reports. Saved-import counts are queried separately, date/owner scoped, distinguished from completed scans, and not inflated by the displayed-evidence limit.
- Fixed the Manager time-only follow-up and the model selector retry/loading lint issue.
- Clarified capability help: workspace-only actions explicitly say no change was made by the chat.
- Repaired stale test harness dependency/session assumptions without disabling product verification or authorization. Shared organization alerts are intentionally visible to Admins; owning another account's connection credentials remains denied.

## How verification was performed

Core business mutations used actual PostgreSQL transactions and real domain/API code with disposable fixtures; transactions rolled back. Provider action tests substituted an isolated HTTP/source transport, not real vendor accounts. Document tests exercised all 18 document types, editable previews, one-use confirmation, attachment checks and encrypted outbox queueing; SMTP fixtures verified acceptance/retry behavior. No audit test sent real staff mail or executed real vendor mutations. Live HTTP read checks used verified disposable accounts and removed them afterward.

Build and TypeScript passed after the source changes. Scoped source lint: 266 files, zero errors, zero warnings; the final security reply file also passed lint. Live HTTP results cover 35 unique page/query destinations for the 64 in-scope entries, 10 Admin read APIs, three non-Admin roles denied Admin endpoints and unauthenticated denial. See [HTTP evidence](verification/admin-http-checks-2026-10-15.json) and [lint evidence](verification/admin-source-lint-2026-10-15.json).

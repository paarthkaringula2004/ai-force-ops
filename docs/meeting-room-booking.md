# AIForce.Ops meeting-room calendar

Dashboard → Meeting Rooms uses the application PostgreSQL database. Admins add actual room names, locations, capacities and equipment. No example rooms are seeded. All active workspace roles can check availability, review and confirm their own reservations, and cancel their own bookings. Other people's meeting titles and identities are not exposed by availability checks.

Availability refreshes every five seconds while the page is visible. Each confirmation rechecks the current database under a room-row transaction lock, so two simultaneous overlapping reservations cannot both succeed. Times are stored in UTC and displayed in the device timezone. Confirmation previews expire after ten minutes, belong to the requesting account, and are idempotent. Meetings must begin in the future within the next year and last at most 24 hours. Disabling a room blocks new reservations and retains existing ones.

MeetRoom's `meeting_rooms` project tool reads current configured rooms, availability and the caller's upcoming bookings. DWP-MAIN-AGENT can delegate to its connected MeetRoom specialist. Chat does not make reservations; the caller reviews and confirms them at `/dashboard/meeting-rooms`. Microsoft 365 / Google Calendar synchronization and invitations are not implemented.

Setup: run `npm run db:migrate` for migrations `0052_meeting_room_bookings.sql` and `0053_meeting_room_removal.sql`, then `node scripts/connect-meeting-room-agents.mjs` to add the tool to existing MeetRoom workflows with a backup, preserving custom settings. Existing shared releases remain frozen; save Share → Done again on the parent agent to distribute the updated connected workflow.

Booking-step buttons return to the time or room fields while keeping entered values. Capacity mismatches are shown beside the attendee field before Review is allowed; undersized rooms cannot be selected. Admins can delete a room after cancelling its upcoming reservations. Each person can remove their own cancelled bookings from My bookings. Both Delete actions ask for confirmation. Rooms disappear from the calendar and removed bookings disappear from the personal list; historical reservation records are retained. Deletion locks the same room row as confirmation, so deletion and a new overlapping reservation cannot both succeed. A deleted room name can be reused when adding a new room.

Test message: “Which meeting rooms are configured, and is AIForce.Ops native booking available?” After adding real rooms: “Check rooms for four people on 12 October 2026, 10:00–11:00 Asia/Kolkata. Show availability and where I can confirm the booking.” Choose a future date when testing later.

Verification: `node tests/meeting-rooms.mjs` tests actual PostgreSQL operations in an isolated schema, including simultaneous confirmations, overlap boundaries, capacity, cancellation, expiry, disabled rooms, identity isolation, authentication and same-origin protection. `node tests/agent-studio.mjs` checks native tool wiring and shared recipient scope with model fixtures. Neither test calls a paid model provider, creates real rooms, or books external facilities.
